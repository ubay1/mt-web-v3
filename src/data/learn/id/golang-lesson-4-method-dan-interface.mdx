# Bab 4: Method dan Interface

Selamat! Kita sudah tiba di bab krusial dalam mempelajari gaya "Pemrograman Berorientasi Objek" (_Object-Oriented_) ala Golang.

Perlu kamu ketahui, Go **tidak memiliki** konsep _class_ seperti Java atau Python. Sebagai gantinya, Go memberikan kita _Method_ pada struct, dan _Interface_ sebagai perekat ajaibnya. Mari kita kupas tuntas.

---

## 1. Apa Itu Method?

_Method_ sejatinya adalah fungsi biasa. Bedanya, method secara khusus ditempelkan ("_attached_") ke suatu tipe data tertentu, biasanya sebuah `struct`.

> **Formula Sederhana:**
> Method = Fungsi + Receiver

Untuk mengerti bedanya, mari kita lihat perbandingan fungsi biasa dan method.

### ❌ Menggunakan Fungsi Biasa

Saat menggunakan fungsi biasa, kita akan mengoper struct sebagai parameter biasa:

```go
type Vertex struct { X, Y float64 }

func Abs(v Vertex) float64 {
	return math.Sqrt(v.X*v.X + v.Y*v.Y)
}

func main() {
	v := Vertex{3, 4}
	fmt.Println(Abs(v)) // Fungsi dipanggil, v dimasukkan sebagai argumen
}
```

### ✅ Mengubahnya Menjadi Method

Kita tinggal memindahkan posisi tipe datanya (disebut **Receiver**) dari dalam parameter, ke sebelah kiri nama fungsi:

```go
type Vertex struct { X, Y float64 }

// Perhatikan "(v Vertex)" yang berada SEBELUM nama fungsi
func (v Vertex) Abs() float64 {
	return math.Sqrt(v.X*v.X + v.Y*v.Y)
}

func main() {
	v := Vertex{3, 4}
	fmt.Println(v.Abs()) // Method dipanggil sebagai "milik" dari v
}
```

> [!TIP]
> **Ke Mana Perginya Parameter di `Abs()`?**
>
> Bagi pemula, perubahan ini mungkin sedikit membingungkan. Mari kita bandingkan:
>
> **1. Fungsi Biasa:** Kita memberikan data dari dalam kurung `()`.
>
> ```go
> func Abs(v Vertex) float64 { return ... }
>
> // Cara panggil:
> Abs(v) // "Tolong hitung nilai milik v"
> ```
>
> **2. Method:** Kita memindahkan parameter ke _sebelum_ nama fungsi (menjadi Receiver).
>
> ```go
> func (v Vertex) Abs() float64 { return ... }
>
> // Cara panggil:
> v.Abs() // "Hei v, tolong hitung nilaimu sendiri"
> ```
>
> **Lalu bagaimana perbandingannya dengan JavaScript/Java?**
> Di bahasa berorientasi objek lain, fungsi di dalam _class_ biasanya menggunakan kata kunci `this` secara ajaib. Pembuatannya menggunakan keyword `new`:
>
> ```javascript
> class Vertex {
>   constructor(x, y) {
>     this.X = x;
>     this.Y = y;
>   }
>   Abs() {
>     return Math.sqrt(this.X * this.X + this.Y * this.Y);
>   }
> }
>
> // Cara panggil di JS:
> const v = new Vertex(3, 4);
> v.Abs();
> ```
>
> Di Golang, **tidak ada kata kunci `this` maupun `class`**. Tulisan `(v Vertex)` di depan nama fungsi itulah cara Golang menyuruh kita membuat "this" secara manual dan memberinya nama `v`. Pembuatannya pun tidak butuh keyword `new`:
>
> ```go
> type Vertex struct { X, Y float64 }
> func (v Vertex) Abs() float64 { return math.Sqrt(v.X*v.X + v.Y*v.Y) }
>
> // Cara panggil di Go:
> v := Vertex{3, 4}
> v.Abs()
> ```
>
> **Intinya:** Di kedua bahasa, kamu **harus** membuat wujud nyata dari cetakannya (`new Vertex` di JS atau `Vertex{}` di Go) sebelum bisa memanggil method-nya!

## 2. Perang Bintang: Value Receiver vs Pointer Receiver

Ini adalah salah satu topik yang sering membuat pemula kebingungan, namun sebenarnya sangat logis.

Ada dua cara sebuah _Receiver_ menerima data struct:

- **Value Receiver (`v Vertex`)**: Bekerja dengan **salinan (copy)** dari data.
- **Pointer Receiver (`v *Vertex`)**: Bekerja dengan **data asli (referensi)**.

Mari kita buktikan dengan contoh!

### 🔵 Skenario 1: Value Receiver

Saat kita menggunakan _value receiver_, Go akan menyalin data aslinya. Artinya, apapun yang kita ubah di dalam method tidak akan mempengaruhi data aslinya di luar method.

```go
type Counter struct {
	value int
}

func (c Counter) Add() {
	c.value++ // Ini HANYA mengubah versi salinan
}

func main() {
	c := Counter{value: 0}
	c.Add()
	fmt.Println(c.value) // Output: 0 ❌ Data asli tidak berubah!
}
```

### 🔴 Skenario 2: Pointer Receiver

Dengan memberikan bintang `*` pada tipe receiver, kita memberikan "alamat" dari data asli. dan kita bisa mengubah data aslinya.

```go
type Counter struct {
	value int
}

func (c *Counter) Add() {
	c.value++ // Mengubah data asli secara langsung
}

func main() {
	c := Counter{value: 0}
	c.Add()
	fmt.Println(c.value) // Output: 1 ✅ Berhasil diubah!
}
```

> [!TIP]
> Walaupun secara teknis kita memanggil `c.Add()` padahal harusnya memakai pointer `(&c).Add()`, Golang cukup pintar untuk membedakannya secara otomatis untuk kita!

---

### Kapan Memilih Pointer vs Value?

Gunakan **Pointer Receiver (`*Struct`)** jika:

1. Kamu berencana **mengubah isi** dari struct tersebut.
2. Struct tersebut ukurannya **sangat besar** (menghindari proses salin data yang berat di memori).
3. Kamu ingin mengikuti _best practice_ paling umum di Golang (konsistensi).

Gunakan **Value Receiver (`Struct`)** jika:

1. Kamu hanya membaca data tanpa perlu mengubahnya.
2. Struct tersebut berukuran kecil dan ringan.

> [!WARNING]
> **Aturan Emas Konsistensi!**
> Jika satu _method_ pada struct mu sudah menggunakan _Pointer Receiver_, pastikan **semua method lainnya pada struct yang sama juga menggunakan _Pointer_**. Jangan mencampurnya! Ini akan meminimalisir banyak _bug_ aneh di masa depan.

## 3. Interface (Kontrak Perilaku)

Apa yang terjadi ketika kita ingin membuat sebuah fungsi yang bisa menerima tipe data `User`, tapi juga bisa menerima `Admin`? Di sinilah **Interface** bersinar.

Secara sederhana, Interface adalah sebuah **kontrak yang berisikan daftar deklarasi method**.

Jika sebuah `struct` memiliki method-method yang sama persis (nama, argumen, dan kembalian) dengan yang dijabarkan dalam kontrak sebuah Interface, maka struct tersebut otomatis dianggap mengimplementasikan Interface tersebut!

Tidak seperti bahasa lain yang menggunakan kata kunci spesifik (seperti `class X implements Y`), **di Go hal ini terjadi secara implisit dan otomatis.**

### Contoh Konkret Interface (Bangun Datar)

Agar tidak bingung dengan struct yang kosong, mari gunakan contoh nyata yang memiliki data: **Menghitung Luas Bangun Datar**.

```go
// 1. Kontrak Interface: Apapun yang punya method Luas(), dia adalah BangunDatar
type BangunDatar interface {
	Luas() float64
}
```

Kita lalu membuat 2 struct berbeda yang memiliki isi datanya masing-masing:

```go
// Struct Pertama: Persegi
type Persegi struct {
	Sisi float64
}

// Persegi memenuhi kontrak BangunDatar
func (p Persegi) Luas() float64 {
	return p.Sisi * p.Sisi
}

// Struct Kedua: Lingkaran
type Lingkaran struct {
	JariJari float64
}

// Lingkaran juga memenuhi kontrak BangunDatar
func (l Lingkaran) Luas() float64 {
	return math.Pi * l.JariJari * l.JariJari
}
```

Karena kedua struct di atas sama-sama memiliki method `Luas() float64`, Golang otomatis menganggap KEDUANYA sebagai `BangunDatar`.

### Mengapa ini berguna?

Karena sekarang kita bisa membuat **satu fungsi universal** yang bisa menerima bangun datar apapun, tanpa harus membuat fungsi terpisah untuk persegi dan lingkaran!

```go
// Fungsi ini menerima APAPUN yang penting sebuah "BangunDatar"
func CetakLuas(b BangunDatar) {
	fmt.Println("Luasnya adalah:", b.Luas())
}

func main() {
	kotak := Persegi{Sisi: 5}
	bulat := Lingkaran{JariJari: 7}

	// Keduanya bisa dimasukkan ke fungsi yang sama!
	CetakLuas(kotak) // Output: Luasnya adalah: 25
	CetakLuas(bulat) // Output: Luasnya adalah: 153.93...
}
```

Antarmuka (_Interface_) membebaskan kamu dari keterikatan tipe spesifik. Memahami Interface adalah kunci untuk naik level menuju developer Golang sejati!
