## Server Actions in React 19

**Server Actions** are one of the most revolutionary features in the React 19 (and Next.js App Router) ecosystem. This feature allows you to **write functions that execute exclusively on the server**, but can be called directly from both client components (_Client Components_) and server components (_Server Components_) without the need to manually create API endpoints (like REST routes or GraphQL).

### Why Are Server Actions So Helpful?

1. **No API Boilerplate**: You no longer need to create `route.ts` or `controller` files, configure CORS, and then call `fetch()` on the client side just to save data to the database.
2. **Built-in Security**: Code inside a Server Action is guaranteed to never leak to the browser (safe for API secrets, direct database interactions, etc).
3. **Progressive Enhancement**: When attached to a `<form action={...}>` tag, this function can still work even if JavaScript in the user's browser is disabled or hasn't finished loading (_hydrated_).

---

### How to Use Server Actions

You define a Server Action by adding the `"use server"` directive at the beginning of the function or at the top of the file.

#### 1. The Old Way (Requires an API Route)

```tsx
// ❌ OLD WAY (React 18 / Traditional)
// Client must call the API
const handleSubmit = async (e) => {
  e.preventDefault();
  const res = await fetch("/api/users", {
    method: "POST",
    body: JSON.stringify({ name: "Ubay" }),
  });
  const data = await res.json();
};
```

#### 2. The New Way with Server Actions

Here is an example of how we directly process a form and return a response from the server without creating a separate API route.

```tsx
// actions.ts (Separate file for Server Actions)
"use server"; // Indicates all functions in this file run on the server

export async function myServerAction(prevState: any, formData: FormData) {
  // Simulate processing time on the server (1.5 seconds delay)
  await new Promise((resolve) => setTimeout(resolve, 1500));

  const name = formData.get("name")?.toString();

  // Input validation
  if (!name || name.trim() === "") {
    return { error: "Name cannot be empty!", success: false };
  }

  // Simulate a fatal error (Uncaught Exception)
  if (name.toLowerCase() === "crash") {
    throw new Error(
      "💥 BAM! The server encountered a fatal error (Exception).",
    );
  }

  // Simulate a business logic error on the server
  if (name.toLowerCase() === "error") {
    return {
      error: "Oops! Simulated logic error from the server.",
      success: false,
    };
  }

  // Success
  return {
    message: `Hello ${name}, Server Action successfully processed your data directly without an API Route!`,
    success: true,
  };
}
```

### Combining Server Actions with `useActionState` & `useFormStatus`

In React 19, the `useActionState` hook pairs perfectly with Server Actions to handle loading states and response messages from the server. Combined with `useFormStatus`, we can easily create a loading button.

```tsx
// Client Component (page.tsx)
"use client";

import { useActionState } from "react";
import { useFormStatus } from "react-dom";
import { myServerAction } from "./actions";

// A submit button component that automatically detects the form's "loading" status
function SubmitButton() {
  const { pending } = useFormStatus();

  return (
    <button type="submit" disabled={pending}>
      {pending ? "Processing on Server..." : "Execute Server Action"}
    </button>
  );
}

export default function TestActionPage() {
  // useActionState replaces useFormState in React 19
  // It accepts (actionFunction, initial_state)
  const [state, formAction] = useActionState(myServerAction, null);

  return (
    // Note that we pass formAction to the form's action property
    <form action={formAction} className="flex flex-col gap-6">
      <input
        type="text"
        name="name"
        placeholder="Type your name (Try typing 'error' or 'crash')..."
      />

      <SubmitButton />

      {/* Display error messages from the server */}
      {state?.error && <p className="text-red-500">{state.error}</p>}

      {/* Display success messages from the server */}
      {state?.success && <p className="text-green-500">{state.message}</p>}
    </form>
  );
}
```

**Conclusion:**
Server Actions eliminate the complexity of building manual APIs for simple operations (like form submissions or data mutations). Just create a function on the server, add `"use server"`, and call it from your components!
