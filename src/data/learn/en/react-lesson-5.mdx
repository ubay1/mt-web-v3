## React 19: Optimistic UI (`useOptimistic`)

**`useOptimistic`** is a hook in React 19 used to implement **Optimistic UI Updates**—instantly displaying data changes on the user interface (_as if the server request has already succeeded_) while the asynchronous server request is still in progress.

Once the asynchronous process on the server completes (or fails), React automatically synchronizes the UI with the official _state_ from the server.

---

### Main Use Cases

- **High Responsiveness**: Users don't need to wait for a network roundtrip (loading spinner) just to see the result of a simple action.
- **Seamless User Experience (UX)**: Ideal for features like sending chat messages, _Like_ buttons, comments, or shopping cart items.

```jsx
import { useOptimistic, useState } from "react";

function UseOptimisticDemo() {
  const [messages, setMessages] = useState<Array<{ text: string; sending?: boolean }>>([
    { text: "Message 1 (Server Synced)" },
  ]);
  const [simulateError, setSimulateError] = useState(false);
  const [errorMessage, setErrorMessage] = useState<string | null>(null);

  const [optimisticMessages, addOptimisticMessage] = useOptimistic(
    messages,
    (currentState, newMessage: string) => [
      ...currentState,
      { text: newMessage, sending: true },
    ]
  );

  const sendMessageAction = async (formData: FormData) => {
    const text = formData.get("message") as string;
    if (!text || text.trim() === "") return;

    setErrorMessage(null);
    // 1. Display optimistically in the UI immediately
    addOptimisticMessage(text);

    // 2. Simulate API delay (1.5 seconds)
    await new Promise((resolve) => setTimeout(resolve, 1500));

    // 3. If error simulation is active
    if (simulateError) {
      setErrorMessage("❌ Server Failed! Message reverted (Automatic Rollback).");
      return;
    }

    // Success -> Update the official state
    setMessages((prev) => [...prev, { text, sending: false }]);
  };

  return (
    <div className="my-6 p-4 border border-line rounded-md bg-white/5 flex flex-col gap-3 w-full">
      <div className="flex flex-col justify-between items-start gap-2">
        <label className="flex items-center gap-1.5 cursor-pointer text-xs text-red-400 font-mono">
          <input
            type="checkbox"
            checked={simulateError}
            onChange={(e) => setSimulateError(e.target.checked)}
            className="accent-red-500 cursor-pointer"
          />
          Simulate Server Error
        </label>
      </div>

      <div className="space-y-1.5 max-h-40 overflow-y-auto font-mono text-xs">
        {optimisticMessages.map((msg, index) => (
          <div
            key={index}
            className={`p-2 rounded flex justify-between items-center ${msg.sending
              ? "bg-accent/10 border border-accent/30 text-accent"
              : "bg-white/10 text-white"
              }`}
          >
            <span>{msg.text}</span>
            {msg.sending && <span className="text-[10px] animate-pulse">(Sending...)</span>}
          </div>
        ))}
      </div>

      {errorMessage && (
        <span className="text-red-400 text-xs font-mono bg-red-500/10 p-2 border border-red-500/20 rounded-sm">
          {errorMessage}
        </span>
      )}

      <form action={sendMessageAction} className="flex gap-2 mt-1">
        <input
          name="message"
          type="text"
          placeholder="Type a message..."
          className="bg-white text-black p-2 text-xs rounded-sm flex-1 font-mono"
        />
        <button
          type="submit"
          className="bg-accent text-black font-semibold px-3 py-1.5 text-xs rounded-sm"
        >
          Send
        </button>
      </form>
    </div>
  );
}
```

---

### What If the Server Request Fails? (Automatic Rollback)

If the request to the server encounters a failure/error:

1. **Automatic Rollback (State Reversion)**:
   The optimistic state from `useOptimistic` **only lives as long as the _Action_ is running (_pending_)**. When the _Action_ function completes, React will re-render the component based on the official `messages` _state_. If the server fails and `setMessages` is never called, the temporary data **automatically disappears from the UI**.

2. **Displaying an Error Message to the User**:
   Use a `try...catch` block inside the _Action_ function. When the error is caught in the `catch` block, simply set an error message (e.g., via `setError(...)`) so the user knows their action failed.
