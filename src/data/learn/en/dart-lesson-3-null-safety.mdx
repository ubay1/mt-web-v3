# Sound Null Safety & Null-Aware Operators

Dart features **Sound Null Safety**. By default, all types are **non-nullable** (cannot contain `null`). This prevents runtime `NoSuchMethodError: The method '...' was called on null` bugs before your code even runs.

---

## 1. Non-Nullable vs Nullable (`Type?`)

To allow a variable to hold `null`, you must explicitly annotate its type with a question mark (`?`):

```dart
void main() {
  // Non-nullable
  String title = 'Dart Mastery';
  // title = null; // ❌ Compile Error: Cannot assign null to non-nullable String

  // Nullable
  String? description;
  print(description); // Output: null

  description = 'Complete guide to modern Dart';
  print(description);
}
```

---

## 2. Null-Aware Operators

### A. Null-Aware Method Invocation (`?.`)

Calls a method or property only if the receiver is not `null`. If it is null, returns `null` safely.

```dart
String? comment;
// print(comment.length); // ❌ Error on nullable type
print(comment?.length);   // ✅ Safe: returns null without crashing
```

### B. Null-Coalescing Operator (`??`)

Provides a fallback value if the left-hand expression resolves to `null`.

```dart
String? nickname;
String display = nickname ?? 'Anonymous';
print(display); // Output: Anonymous
```

### C. Null-Coalescing Assignment (`??=`)

Assigns a value only if the target variable is currently `null`.

```dart
int? points;
points ??= 10; // points is now 10
points ??= 50; // points remains 10
```

### D. Null Assertion Operator (`!`)

Tells the compiler: _"I assert that this nullable expression is definitely not null here"_. If it is null at runtime, it throws an exception.

```dart
String? rawToken = 'auth_token_xyz';
String validToken = rawToken!; // Cast from String? to String
```

## 3. The `late` Keyword (Late Initialization)

### ❓ Why Do We Need `late`?

In Dart with Null Safety, a **non-nullable** variable (e.g., `String name;`) **must be assigned a value immediately when declared**. Otherwise, the compiler throws an error.

However, in real applications:
1. You **cannot initialize the value immediately** (e.g., it will only be available after user login, hardware sensor readings, or during Flutter's `initState()` lifecycle).
2. But you **DO NOT want to make it nullable (`String?`)**, because you know that once initialized, this variable is **guaranteed to always hold a valid value and should never be null**. Making it nullable would force you to write tedious `?.` or `!` operators everywhere in your codebase.

> [!TIP]
> **💡 The Promise to the Compiler:**
> The `late` keyword is your formal **"promise"** to the Dart compiler:
> *"Hey Dart, this is a non-nullable variable. I don't have its value right now, but I **PROMISE** I will initialize it before any code tries to read it!"*

---

### A. Example 1: Delayed Initialization

```dart
void main() {
  // Without 'late', this line would fail compilation because non-nullables must be initialized
  late String username;

  print('1. Initializing application...');

  // Assign the value later before use:
  username = 'Ubay';

  // Read normally as a standard non-nullable String without null-checks (?.)
  print('2. Welcome back, $username!');
  print('3. Character count: ${username.length}');
}
```

---

### B. Example 2: Usage in a Service / Controller (Real-World)

Imagine the service class is located in a separate file (`auth_service.dart`), and we import it into our main entry point (`main.dart`):

```dart
// =========================================================================
// 📁 File: lib/services/auth_service.dart
// =========================================================================
class AuthService {
  // We know the token is non-nullable, but it only arrives after successful login
  late final String authToken;

  void login(String email, String password) {
    // Simulating authentication and receiving token
    authToken = 'jwt_secret_token_12345';
    print('Successfully authenticated for: $email');
  }

  void fetchUserProfile() {
    // Access authToken cleanly without defensive null-checks
    print('Fetching profile using token: $authToken');
  }
}
```

```dart
// =========================================================================
// 📁 File: bin/main.dart
// =========================================================================
// In Dart, simply import the file path (no need for curly braces { } like in JS)
import 'package:my_app/services/auth_service.dart';
// Or using relative path: import './services/auth_service.dart';

void main() {
  final auth = AuthService();
  auth.login('alex@example.com', 'secret123'); // 1. 'authToken' is initialized here
  auth.fetchUserProfile();                     // 2. Safely read here without crashing
}
```

> [!NOTE]
> **💡 Import Syntax: Dart vs JavaScript:**
> - In **JavaScript/TypeScript:** `import { AuthService } from './services/auth_service.js';`
> - In **Dart:** `import 'services/auth_service.dart';` (all public classes and top-level functions in the file are automatically available without curly braces `{}`). If you only want to import a specific class, use: `import 'services/auth_service.dart' show AuthService;`.

### C. Example 3: Lazy Evaluation (Performance Optimization)

When you assign an expensive function call to a `late` variable, that function is **NOT EXECUTED** until the variable is accessed for the very first time!

```dart
String heavyCalculation() {
  print('⏳ Running heavy computation...');
  return 'Processed Payload';
}

void main() {
  // heavyCalculation() is NOT called when this line is declared:
  late String result = heavyCalculation();

  print('App loaded.');

  // heavyCalculation() is ONLY executed when 'result' is read here:
  print('Displaying: $result');
}
```

---

### ⚠️ Common Pitfall: `LateInitializationError`

Because you promised the compiler that the variable would be initialized before read, the compiler trusts you completely. If you **forget to initialize it before reading**, your application will throw a fatal **runtime crash**:

```dart
void main() {
  late String userAddress;

  // 💥 RUNTIME CRASH: LateInitializationError: Field 'userAddress' has not been initialized.
  // print(userAddress); 
}
```

> [!CAUTION]
> Use `late` **only when you are 100% confident** initialization always happens before access (such as in Flutter `initState` or setup flows).
