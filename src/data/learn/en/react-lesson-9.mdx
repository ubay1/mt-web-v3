## React Server Components (RSC), Client vs Server, & When to Use Them

Although introduced previously (alongside Next.js), React 19 solidifies _Server Components_ natively. By default, if you use a framework like Next.js, components are rendered on the server.

- **Advantages**: Reduces the JavaScript bundle size sent to the client (because dependencies stay on the server) and speeds up data access (can query the database directly in the component).
- Components that require interaction (like _onClick_ or _useState_) must be explicitly marked with the `"use client"` directive.

In the era of React Server Components (RSC) such as in the Next.js App Router, understanding when to keep components on the Server and when to add `"use client"` is crucial for website performance.

### 🛑 `"use client"` Does NOT Mean "Only Rendered in the Browser"

This is one of the most common misconceptions. Despite its name, a `"use client"` component is **still rendered on the server** to generate the initial HTML (whether statically/SSG or dynamically/SSR).

The main difference lies in the **JavaScript**:

- **Server Component (Default)**: Only dead HTML is sent to the browser. Its JavaScript code is completely removed from the bundle downloaded by the user.
- **Client Component (`"use client"`)**: The JavaScript code is sent along to the browser. The browser then performs _Hydration_ so the component can come alive and respond to click interactions, typing, etc.

---

### When Should You Add `"use client"`?

Add `"use client"` at the very top line (before any _import_ statements) **ONLY IF** the component requires:

1. **Interactivity (User Events)**: Contains `onClick`, `onChange`, `onSubmit`, or drag-and-drop functionality.
2. **State & Lifecycle Hooks**: Uses `useState()`, `useEffect()`, `useRef()`, `useReducer()`, or Custom Hooks that call them.
3. **Browser APIs**: The component interacts with browser-only APIs, such as `window`, `document`, `localStorage`, or Geolocation.

---

### When to Keep Server Components (Default)?

Do not add `"use client"`. Leave the file as a Server Component **IF** the component only:

1. **Displays Static UI**: It's just text, images, layout, or dead articles.
2. **Performs Server Data Fetching**: Queries a database directly or calls an internal secret API using `async/await`.
3. **Requires Server Modules (Node.js)**: Uses OS-level packages like `fs` (file system), `crypto` for advanced security encryption (like HPKE), or accesses secret `.env` variables.

---

### 💡 Best Practice: Moving Client Components Down the Tree

For maximum performance, the official Next.js documentation recommends this pattern: **Do not put `"use client"` on top-level layout components (like `page.tsx` or `layout.tsx`).**

Keep your main `page.tsx` as a Server Component to fetch data as fast as possible and generate super lightweight HTML. Then, isolate the interactive parts into separate, smaller components.

**Incorrect Example ❌:**
Adding `"use client"` to the entire `Layout.tsx` file just because there is one Search Bar at the top that uses `useState`. Consequently, the entire layout and page content is forced to become client-side JavaScript.

**Correct Example ✅:**
Extract the search logic into a dedicated file named `SearchBar.tsx`. Add `"use client"` **only to that small file**. Then, _import_ `<SearchBar />` into `Layout.tsx`, which maintains its purity as a Server Component.

```tsx
// 1. SearchBar.tsx (Client Component - At the end of the branch)
"use client";
import { useState } from "react";

export default function SearchBar() {
  const [query, setQuery] = useState("");
  return (
    <input onChange={(e) => setQuery(e.target.value)} placeholder="Search..." />
  );
}

// 2. Layout.tsx (Server Component - The main trunk)
import SearchBar from "./SearchBar";
import StaticLogo from "./StaticLogo";

export default function Layout({ children }) {
  return (
    <div>
      <nav>
        <StaticLogo />
        <SearchBar /> {/* Only this component loads JS */}
      </nav>
      <main>{children}</main>
    </div>
  );
}
```

By pushing _Client Components_ as far down the UI tree ("to the leaves") as possible, the JavaScript bundle sent to users will be remarkably small, and your website will be significantly faster!
