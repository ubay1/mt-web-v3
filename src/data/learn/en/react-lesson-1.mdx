## Introduction to React

**React.js** is an open-source JavaScript library created by Meta (Facebook) for building user interfaces (**UI**), specifically for **Single Page Applications (SPA)**.

Unlike traditional approaches where every page transition reloads the entire browser, React only updates the parts of the UI that change quickly and efficiently.

---

## 3 Core Concepts of React

Before diving into code, there are three pillar concepts you need to understand:

1. **Component-Based:** The UI is broken down into small, independent, and reusable pieces, such as buttons, headers, or profile cards.
2. **Virtual DOM:** React creates a lightweight copy of the page structure (DOM). When data changes, React compares this copy with the previous version (the *reconciliation* process) and only updates the elements that actually changed in the real browser.
3. **Declarative:** You simply define *how the UI should look based on the data/state*, and React handles the updating process automatically.

---

## Basic React Foundation

### 1. JSX (JavaScript XML)

JSX is a syntax extension for JavaScript that allows you to write HTML-like code directly within your JavaScript files.

```jsx
// JSX Example
const Greeting = () => {
  const name = "Alex";
  return <h1>Hello, {name}! Welcome to React.</h1>;
};
```

> **Note:** Code inside curly braces `{}` is evaluated as pure JavaScript expressions.

---

### 2. Components

Modern React components are written using **Functional Components** (regular JavaScript functions that return JSX).

```jsx
// Simple button component
function PrimaryButton() {
  return (
    <button className="btn-primary">
      Click Me
    </button>
  );
}
```

---

### 3. Props (Properties)

Props are used to **pass data** from a parent component to a child component. Props are *read-only* (they cannot be modified by the receiving component).

```jsx
// Child Component
function UserCard(props) {
  return (
    <div className="card">
      <h3>Name: {props.name}</h3>
      <p>Role: {props.role}</p>
    </div>
  );
}

// Parent Component
function App() {
  return (
    <div>
      <UserCard name="Budi" role="Frontend Developer" />
      <UserCard name="Siti" role="UI/UX Designer" />
    </div>
  );
}
```

---

### 4. State (`useState`)

**State** is internal component data that is dynamic and can change over time due to user interactions (like button clicks, text inputs, or data from APIs). When the state changes, React will *re-render* that component.

React provides a *Hook* called `useState` to manage state:

```jsx
import React, { useState } from 'react';

function Counter() {
  // useState keeps track of the current value (count) and the setter function (setCount)
  const [count, setCount] = useState(0);

  return (
    <div style={{ textAlign: 'center', marginTop: '20px' }}>
      <h2>Count: {count}</h2>
      <button onClick={() => setCount(count + 1)}>
        Add 1
      </button>
      <button onClick={() => setCount(count - 1)} style={{ marginLeft: '8px' }}>
        Subtract 1
      </button>
    </div>
  );
}
```

---

## Summary: Props vs State

| Feature | Props | State |
| --- | --- | --- |
| **Definition** | Data passed from the outside (Parent) | Internal data belonging to the component itself |
| **Triggers Re-render** | If the props sent by the Parent change | If the state is modified using the updater function |
| **Data Mutability** | Immutable (Read-only) | Mutable (Can be changed via `setState`) |
